## Bugs

1. **Falsos positivos de `public` sobre objetos del sistema** (sección 4):
   `sys.database_permissions` trae cientos de concesiones de fábrica de
   `public` sobre vistas y procedimientos del sistema (`major_id < 0`); la
   tabla se llenaría de `REVISAR` sin sentido.
   - ↳ Respuesta (Claude): **Corregido.** Se excluyen los permisos sobre
     objetos con `major_id < 0` o de los esquemas `sys` e
     `INFORMATION_SCHEMA`, y los de esos esquemas.
2. **`HAS_PERMS_BY_NAME` en NULL tomado como "el objeto no existe"**: también
   da NULL cuando la cuenta impersonada no ve el objeto; un objeto sin ningún
   permiso (el estado ideal para `_migraciones`) saldría como inexistente, y
   un objeto necesario sin permisos saldría INFO en vez de ALERTA.
   - ↳ Respuesta (Claude): **Corregido.** La existencia se comprueba antes de
     impersonar, con la cuenta de quien corre el script. Si existe, NULL cuenta
     como "no puede". Si no existe y la API lo necesita, es ALERTA.
3. **Cualquier `DENY` salía como OK**, aunque rompiera la API.
   - ↳ Respuesta (Claude): **Corregido.** Un DENY sale como INFO con la nota de
     que la sección 5 dice si quita algo que la API usa; ahí un "no" en algo
     necesario es ALERTA.
4. **`db_denydatareader`/`db_denydatawriter` en la API salían como OK.**
   - ↳ Respuesta (Claude): **Corregido.** Para la API sólo `db_datareader` es
     OK, `db_datawriter` es REVISAR y **cualquier otro rol** es ALERTA.
5. **`guest` duplicado con dos estados** (REVISAR y ALERTA).
   - ↳ Respuesta (Claude): **Corregido.** El CONNECT de toda la base se excluye
     del listado general para todos, `guest` incluido; queda su control propio.
6. **`USE [MdcMaquinaria]` sin guardia**: si la base no existe, el script
   seguiría en `master`.
   - ↳ Respuesta (Claude): **Corregido, con un matiz.** El script no se
     aborta: sin `-b`, `sqlcmd` y SSMS siguen con el siguiente lote y la
     tabla final sale. Lo grave era otro efecto del mismo error: las
     secciones 4 a 6 habrían medido `master` y dado datos falsos. Ahora, si
     tras el `USE` la base actual es del sistema, se anota una ALERTA y
     `SET NOEXEC ON` se salta las secciones 4 a 6; `SET NOEXEC OFF` antes del
     resultado garantiza que la tabla final salga.
7. **`EXECUTE AS USER … REVERT` sin `TRY…CATCH`.**
   - ↳ Respuesta (Claude): **Corregido.** Va en `TRY…CATCH`; en el CATCH se
     hace `REVERT` si sigue impersonando y se anota una ALERTA con el mensaje.
